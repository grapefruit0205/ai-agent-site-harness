# 인터랙티브 에디토리얼 사이트 제작

글의 논증과 웹의 상호작용을 함께 설계한다. 기존 프로젝트에서는 사용자가 선택한 프레임워크와 배포 방식을 유지하고, 새 프로젝트에서는 콘텐츠를 정리한 뒤 기술 구성을 정한다.

## 작업 흐름

1. 제공된 자료에서 확인 가능한 사실, 필자의 해석, 아직 확인하지 못한 주장을 구분한다.
2. 독자가 페이지를 다 읽은 뒤 답할 질문을 하나 정하고 각 장면의 역할을 배치한다. 이때 [콘텐츠와 정보 구조](references/content-architecture.md)를 읽는다.
3. 장면마다 텍스트, 도표, 인터랙션 중 이해에 필요한 표현 하나를 우선한다. 화면마다 모든 표현을 동시에 쓰지 않는다.
4. 시맨틱 HTML과 정적 본문을 먼저 구현하고, 비교·순서·상태 변화처럼 조작이 이해를 바꾸는 장면에만 인터랙션을 추가한다.
5. 색상 토큰, 타이포그래피 역할, 중앙 축, 반응형 전환을 정할 때 [시각·반응형 시스템](references/visual-system.md)을 읽는다.
6. 완료를 보고하기 전에 [검증 계약](references/verification-contract.md)에 따라 콘텐츠, 상호작용, 레이아웃, 빌드를 확인한다.

## 지켜야 할 경계

- 사용자가 선택한 프레임워크, 호스팅, 브랜드 방향을 임의로 교체하지 않는다.
- 장문 본문을 카드 모음으로 축약하지 않는다. 텍스트 장면과 시각 장면 사이에 읽는 리듬을 만든다.
- 원본 사이트의 문구, 로고, 고유한 시각 자산을 새 프로젝트에 그대로 복사하지 않는다. 구조와 검증 방법만 재사용한다.
- 서버 기능이 필요하다는 요구와 배포 증거가 없으면 백엔드를 추가하지 않는다.
- 외부 배포, DNS, 클라우드 리소스 변경은 별도 승인을 받은 뒤 실행한다.
