# 콘텐츠와 정보 구조

## 먼저 만드는 표

코드를 열기 전에 장면 계약을 작성한다.

| 항목 | 확인할 내용 |
| --- | --- |
| 독자의 질문 | 이 장면을 지나면 독자가 무엇을 이해해야 하는가 |
| 핵심 주장 | 한 문장으로 설명할 수 있는가 |
| 근거 | 출처가 있는 사실인지 필자의 해석인지 |
| 표현 방식 | 본문, 비교표, 흐름도, 시뮬레이션 중 무엇이 가장 짧게 설명하는가 |
| 인터랙션의 역할 | 조작 전후에 독자의 이해가 달라지는가 |
| 모바일 대안 | 좁은 화면에서 같은 의미를 어떤 순서로 보여주는가 |
| 인수 조건 | 문장, 링크, 접근성, 동작을 어떻게 검증하는가 |

근거가 없는 통계나 인용문을 만들지 않는다. 기업이 발표한 수치는 기업 자체 발표임을 본문 가까이에 표시한다.

## 논증의 뼈대

자료에 맞는 순서만 선택한다. 다음 역할을 모두 별도 장으로 만들 필요는 없다.

- 독자가 검색한 질문이나 현업 장면으로 범위를 정한다.
- 생소한 개념을 짧게 정의하고 인접 개념과 구분한다.
- 기술이 필요한 원인을 먼저 보여준 뒤 이름을 붙인다.
- 실패 장면이나 비교 장면으로 추상적 설명을 검증한다.
- 독자가 다음 작업에서 사용할 판단 기준으로 닫는다.

한 장에 강한 시각 모듈이 여러 개 겹치면 FIELDNOTE나 하위 페이지로 분리한다. 독자가 계속 UI를 해석해야 한다면 본문과 시각 요소의 순서를 다시 조정한다.

## 한국어 편집

- 제목의 강제 줄바꿈은 의미 단위에만 사용한다. 본문에는 `<br>`을 반복하지 않는다.
- 제목 줄은 `span`으로 나누되 모바일 CSS에서 자연스러운 줄바꿈으로 풀 수 있게 한다.
- 한 문단에는 한 주장만 둔다. 문단 첫 문장이 주장을 말하고 뒤 문장이 근거와 한계를 설명한다.
- RAG, MCP, LLMOps 같은 용어는 처음 등장할 때 한 문장으로 설명한다.
- 링크는 주장과 가까운 위치에 둔다. 출처 목록만으로 본문 근거를 대신하지 않는다.

## 콘텐츠와 코드의 경계

반복되는 장면 데이터는 배열이나 콘텐츠 파일로 분리한다. 장면 고유의 도표는 컴포넌트로 유지한다. 문구 하나를 바꾸기 위해 레이아웃 코드를 해석해야 한다면 콘텐츠 경계가 부족한 상태다.
