# 검증 계약

프로젝트의 `package.json`, 프레임워크 설정, 저장소 지침에서 실제 명령을 먼저 확인한다. 아래 검증 유형을 현재 스택의 명령으로 실행한다.

## 콘텐츠

- 핵심 제목, 장 ID, 출처 링크가 빌드 결과에 들어 있는지 확인한다.
- 확인 가능한 사실과 필자의 해석이 섞이지 않았는지 검토한다.
- 메타데이터, OG 이미지, `lang="ko"`를 확인한다.
- 링크와 과정명 및 날짜를 원본 자료와 대조한다.

## 상호작용과 접근성

- 키보드만으로 주요 장면을 열고 닫고 이동할 수 있는지 확인한다.
- Escape로 모달을 닫은 뒤 포커스가 실행 버튼으로 돌아오는지 확인한다.
- 토글 상태, 진행 단계, 동적 결과를 보조기기에 전달하는지 확인한다.
- 모션 감소 설정에서도 콘텐츠가 숨지 않는지 확인한다.

## 레이아웃

- 한국어 제목의 의미 단위가 유지되고 컨테이너 밖으로 나가지 않는지 확인한다.
- 본문과 제목 및 도표가 같은 중앙 축을 사용하는지 확인한다.
- 이미지가 비율을 유지하며 부모 너비를 넘지 않는지 확인한다.
- 넓은 화면, 태블릿 전환점, 작은 모바일 화면에서 가로 스크롤과 잘림을 점검한다.

스타일 회귀 테스트는 특정 CSS 문구의 존재보다 계산된 스타일이나 실제 렌더링 결과를 검사한다.

## 실행

1. lock 파일이 있으면 깨끗한 체크아웃에서 `npm ci`로 설치한다.
2. lint와 상호작용 테스트를 실행한다.
3. 프로덕션 빌드를 실행한다.
4. 정적 결과물을 서버 렌더링하거나 로컬 HTTP로 열어 핵심 경로를 확인한다.
5. 실패한 명령과 출력은 지우지 않고 수정 전 증거로 남긴다.

정적 호스팅 프로젝트에서는 서버 전용 API 사용 여부와 실제 산출물 경로를 확인한다. 배포 검증은 빌드 검증과 분리하며 사용자의 승인 없이 클라우드 상태를 바꾸지 않는다.
