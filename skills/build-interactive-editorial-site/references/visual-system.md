# 시각·반응형 시스템

## 토큰부터 정한다

`:root` 또는 테마 파일에 최소 토큰을 둔다.

- 종이 배경, 표면, 기본 글자, 보조 글자
- 주 강조색과 상태 색상
- 기본 선과 강한 선
- 본문 최대 너비와 페이지 여백
- 제목, 본문, UI, 코드의 글꼴 역할

개별 컴포넌트에 임의 색상과 크기를 계속 추가하지 않는다. 토큰을 바꾸면 사이트 전체의 색조와 대비가 함께 바뀌어야 한다.

## 에디토리얼 축

- 본문은 왼쪽 정렬을 유지하되 모든 장이 같은 중앙 컨테이너 축을 사용하게 한다.
- 제목, 리드문, 도표의 최대 너비를 따로 정한다. 한 요소의 너비가 다른 장의 정렬을 밀지 않게 한다.
- 이미지에는 `display: block`, `max-width: 100%`, `height: auto`, 중앙 정렬을 기본값으로 둔다.
- 장 전체를 카드로 감싸지 않는다. 배경, 여백, 타이포그래피만으로 구분할 수 있는 장은 평면으로 둔다.

한국어 제목에는 본문보다 여유 있는 행간과 `word-break: keep-all`을 적용한다. 긴 기술 용어 때문에 넘칠 때는 `overflow-wrap: break-word`를 함께 사용한다.

## 반응형 전환

브레이크포인트는 기기 이름보다 레이아웃이 무너지는 지점에서 정한다. 현재 참조 구현의 1100px, 820px, 540px은 출발점일 뿐 새 프로젝트의 고정 규칙이 아니다.

- 넓은 화면: 본문과 도표가 같은 중심축을 유지하는지 확인한다.
- 중간 화면: 2열 구조를 1열로 바꾸고 장식보다 읽는 순서를 우선한다.
- 모바일: 고정 사이드 목차를 축소하거나 문서 흐름 안으로 옮긴다.
- 모달과 펼친 책: `100dvh` 안에서 닫기 버튼과 본문 스크롤을 사용할 수 있게 한다.
- 모든 화면: `overflow-x`로 문제를 숨기기 전에 넘치는 자식 요소의 너비를 고친다.

## 인터랙션 선택

인터랙션은 다음 세 유형에 적합하다.

- 비교: 권한 넓게와 최소 권한처럼 같은 입력의 다른 결과
- 순서: 사용자 요청부터 정책 판단과 감사 로그까지 이어지는 단계
- 구조 탐색: 책이나 FIELDNOTE를 열어 요약에서 세부 내용으로 이동

버튼은 실제 `button` 요소를 사용하고 현재 상태를 `aria-pressed`나 `aria-current`로 알린다. 모달은 제목을 연결하고 Escape 닫기와 포커스 복귀를 지원한다. 자동 재생과 스크롤 애니메이션은 `prefers-reduced-motion`에서 줄인다.

애니메이션이 없어도 내용과 순서가 이해돼야 한다. 모바일에서는 3D 효과보다 읽기와 닫기 동작을 우선한다.
